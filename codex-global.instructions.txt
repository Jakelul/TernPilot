## TernPilot — Token Cat switch and Astra/Claude/Gemini cooperation

- The user requested cooperation from Codex conversations: Astra coordinates and
  Claude Code and Gemini contribute scoped work using their existing accounts. At the
  start of each substantive user request, and before each new delegation, run
  `python3 {{INSTALL_DIR}}/control.py status`. Never rely on a cached ON state.
  Missing, invalid or unavailable control state means OFF. OFF prevents new
  TernPilot delegations; already accepted jobs finish, as the user selected.
  The Token Cat TernPilot toggle changes this same local control file.
  While OFF, do not bypass it by calling dev, Claude or Gemini directly for automatic
  delegation. Only an explicit user request for a manual provider run overrides it.
- When ON, keep the selected Codex app model as coordinator. For a task with a
  useful separable part, choose a suitable provider rather than duplicating it:
  use Gemini for project requirements, comparisons, summaries and initial plans;
  use Claude for complex diagnosis, independent review and bounded implementation.
  Astra and Opus are peer strong engines; TernPilot CLI calls use medium effort
  and standard speed, and Gemini uses the configured Argon high model with high effort.
  Never change the selected Codex app model or its global settings for this.
  Astra keeps primary implementation, integration and final judgment as appropriate.
  Use the existing Claude text helper for substantive non-Git discussions.
  Do not wait for quota exhaustion before assigning useful work to either provider. Avoid duplicated full-task work, token
  ratio targets or unnecessary calls for short answers and trivial edits.
  Simple answers and live app/connector actions stay in the current conversation.
  Explicit no-delegation, direct execution, or provider limits take precedence.
- For text analysis/review/drafting, write a private scoped task file, then use:
  `python3 {{INSTALL_DIR}}/assist.py --task-file TASK_FILE`
  This Claude consultation has no tools, uses an isolated temporary directory,
  and does not receive repository files or conversation history automatically.
  Include needed excerpts yourself. Check completion and incorporate the useful
  result; do not equate a submitted call with a successful answer.
- For a bounded implementation in an existing Git repository, read applicable
  instructions and inspect existing changes first. To let Claude handle a
  separable implementation while Astra coordinates, use:
  `python3 {{INSTALL_DIR}}/job.py submit --repo REPO --task-file TASK_FILE --engine claude --no-fallback`
  Do not edit the same repository concurrently. For an Astra-led independent
  job with quota continuation, omit --engine/--no-fallback: it starts Astra,
  switching to Claude only on explicit usage exhaustion. Do not duplicate a
  running coordinator's whole task in another Astra worker. Do not create Git
  repositories just for routing.
- For a Gemini project analysis/planning portion, read installed config.json and
  use `python3 {{INSTALL_DIR}}/job.py submit --repo REPO --task-file TASK_FILE --engine gemini --no-fallback`.
  This Mac uses Antigravity agy with its configured, currently offered Gemini
  high model. It is a project worker with an analysis-only task instruction, not a tools-disabled text helper or a
  guaranteed read-only sandbox. Request analysis without edits, respect normal
  tool permissions, and check its resulting diff; never silently undo changes. Do not run it
  concurrently with writes to that same repo; it may inspect relevant files.
  If Gemini is unavailable, report that fact and continue permitted work in the
  coordinator; do not downgrade a hard implementation task to Flash or add APIs.
  Never force all three providers to run on every request. A single dev/job run
  does not automatically execute a plan/implement/review pipeline after success.
- Include only the task's necessary request, constraints, excerpts, decisions,
  completed work, failed checks and remaining steps. The user authorized sending
